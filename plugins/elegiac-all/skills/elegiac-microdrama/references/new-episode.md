# Wizard: Create a New Episode

## Outcome

Create or resume one canon-consistent Episode Board and, if requested and authorized, one finished episode. Do not duplicate Production memory, Boards, artifacts, or already completed beats.

## Workflow

1. Resolve the Production from the known ID or `list_productions`. Read `00 — Series Bible`, the series manifest/spine (including `styleLine`, `lookLine`, `stillModel`, `voices`, `locations[].plates`, `branding`), prior episode Board, Cast, StyleSystem, relevant locations/assets, and local Production Kit state. If any of `styleLine`, `lookLine`, a voice for every speaking role, or the branding package is missing, resolve it now with one consolidated ask; it is cheaper here than at the edit.
2. Determine the canonical next episode from structured metadata. If that Board exists unfinished, resume it: read `episode-blueprint.json` and skip every stage whose asset ids are set. Never infer the episode solely from Board count.
3. Reconcile a continuity brief: previous cliffhanger; answer owed now; character, relationship, wardrobe, injury, prop, vehicle, location, time, and lighting state; open loops; episode movement; prohibited contradictions.
4. Draft the episode promise: hook, dominant want/conflict, two escalations, turn, spike/decision, caused cliffhanger, and `opens/advances/resolves`. Reject a plan that merely stalls.
5. Write and perform-time the script. Default to one scene and the selected profile's duration. Give the opening three seconds and final five seconds special scrutiny. **Build the shot ledger and run `check-shot-budget.mjs` here.** Speaking cuts are estimated at 2.6 words per second plus 0.75 s of handles, silent cuts at their target; bookends are added from the branding package. If the estimate exceeds the profile target, present a specific trim list (which lines, which inserts) and settle it with the user before a single stem exists. An App Standard episode that reaches the edit at 89 s has no cheap fix left (Tessa S01E01). Stop here if the user asked only for a plan or script.
6. Create exactly one canonically named Board only if it does not exist and the title is locked. When approved Cast/location anchors exist, stage with `create_scene_board_from_production_memory`; otherwise use the appropriate existing Board creation tools. Ambiguous or missing required identity blocks spend.
7. Add or update blueprint, creative direction, script revision, shot list, storyboard beats, sources, and edit-manifest view. Use `update_board_artifact` instead of duplicate cards. Every shot in the ledger carries `plateId`, `framing`, `faceCount`, `mouthVisible`, and for inserts `wardrobeAnatomy`, before any generation.
8. **Coverage set.** List the staging positions the ledger uses and confirm a plate exists for each and for every vehicle in the scene. Generate the missing plates first (`production-pipeline.md`, stage 0); they are the references every still will pin to.
9. Reframe the proof shots: `list_framings` → one `enhance_prompt` call with `shots[]` and the scene's references (plate first), then generate the proof with `generate_shots` using the enhanced prompts verbatim plus the style line. Quote/cap a 4–6-frame still proof that includes one adjacent pair from the same plate. Review with the `continuity-gate.md` checklist. Curate or surgically repair before motion.
10. Produce the clips through `production-pipeline.md` unless the user overrides it: stage 1 dialogue stems (one job per line, the role's stored `voiceId`, audio tags for performance), measured and written back as `clipDurationSeconds`; stage 2 framed 9:16 stills for every cut in plate batches; the continuity gate and the stills animatic (`build-stills-animatic.mjs`), approved with the word "animate"; stage 3 MiniMax H3 Max Turbo clips at 768p generated at stem length plus a handle, pilot batch first; stage 4 VEED Lipsync V2 only for cuts with one visible speaking face. Quote each stage as one batch, keep takes tied to shot IDs, record rejections and the ledger fields, and reuse style/cast IDs.
11. Export/freeze sources and construct the hashed edit manifest. Copy `series-manifest.branding` into `edit-manifest.branding` with the `later` opening policy (overlay mark or none; a splash after Episode 1 needs a recorded reason) and the same mark and sting hashes as the previous episode; if the series package is missing, run the checklist in `branding.md` before writing the manifest. Captions default to a sidecar (`burnIn: false`). Build the HyperFrames handoff; run checks, inspect representative frames/contact sheet, review with sound and muted, and obtain final preview approval before render.
12. Probe the rendered output and close the ledger: loops resolved/advanced/opened, character/location/vehicle deltas, exact next-episode handoff, credits, files, review proxy, and Elegiac registration state.

## Resumption rules

- The highest revision of a canonical artifact wins only when its lineage is explicit; never overwrite an edited local file silently.
- Completed source jobs are reused. A retry after permission or transport failure uses the identical call and idempotency key. A regeneration after a stall or a rejected still uses a fresh key (`-v2`, `-v3`).
- After a context compaction or a usage-limit resume, the blueprint is the state, not the conversation: never refire a shot whose stage asset id is set, and never re-run a poll for a job already marked `ready`.
- A title change does not change `SxxExx`; an episode number change is a migration that must update Board, shot, asset, manifest, and filename references together.
- If the previous episode is unfinished or its cliffhanger is unknown, expose that gap before inventing continuity.
- A changed series mark, sting, or typography between episodes is a rebrand: state it in the call sheet and update `series-manifest.branding` rather than diverging silently.
- A still changed after the animatic was approved reopens the gate for that cut (`animatic.stillHashes` no longer matches).
