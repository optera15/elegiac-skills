# Wizard: Create a New MicroDrama

## Outcome

Create or deliberately reuse one Elegiac Production, establish a complete no-spend season design and durable series memory, create one production-ready Episode 1 Board, and—only when the user continues through cost and review gates—finish Episode 1.

## Workflow

1. **Interpret the seed.** Restate it as protagonist + desire + obstacle + contradiction + renewable engine. Surface a concrete ethical, rights, or logic risk without turning harmless fiction into a compliance interview.
2. **Run the intake once.** Before any style card, bible prose, or board exists, ask one consolidated question with a recommended default for each line, and write the answers to `series-manifest.json`:
   - **Look**: does the user have a look in mind or reference images? Record `styleLine` (appended verbatim to every image prompt) and `lookLine` (appended verbatim to every location and composite prompt), plus any reference image URLs. Do not draft a visual style of your own until this is answered; a style invented first gets rewritten into every card later (Tessa: "Gulf Coast Naturalism" was written into the bible, the style card, and four location cards, then replaced by the user's Ektar pastel look).
   - **Control**: Fast Track, Co-Creator, or Director and department overrides.
   - **Profile**: App Standard (60 × 75 s), Creator 24/30, or Custom; rating; locale; audience.
   - **Voices**: ElevenLabs voice IDs the user already owns, or permission to cast from the built-in voices.
   - **Still model**: the show's keeper still model and price (default `gpt-image-2` at medium quality and 2K, 15 credits; `muse-image`, 3 credits, for staging and blocking loops). State it; the user should never later discover which model was used.
   - **Foundation portraits** are 4:3 and the 7-panel identity sheet is 4:3; say so, do not ask.
   Infer what is safe to infer; ask only what materially alters the result.
3. **Run a concept round.** Offer three compact directions varying one meaningful axis—tone, relationship, setting, or engine—and recommend one. "None of these" and direct authorship remain available.
4. **Lock the show promise.** Title candidates, logline, audience promise, theme, primary genre, emotional engine, trope package, visual form, and a one-sentence "why Episode 2?"
5. **Create the workspace.** Call `list_productions` first. After the applicable user checkpoint, call `create_production` with `microdrama`, genre/form, and locale tags; then `create_brainstorm_board` as `00 — Series Bible`, `add_creative_roadmap`, and `add_creative_direction`. Do not use Showrunner.
6. **Build the bible.** Write world rules, principal wants/wounds/secrets/arcs, relationships, recurring locations/props/vehicles, dialogue rules, prohibited clichés/content, rating, and rights. Cast a voice for **every speaking role that the season plan names**, principals and recurring bit parts, and store each as `voiceId`; the same ID is reused for that role in every episode. Write a `wardrobeAnatomy` line per principal (sleeve length, skin, hands, hair state, jewellery) that inserts will copy verbatim. Mirror durable facts with character tools and Board artifacts.
7. **Plan the whole season in text.** Use the selected profile and the six movements in `craft.md`. For every episode store promise, hook, turn, cliffhanger, and `opens/advances/resolves`. Do not generate a season of media.
8. **Develop recurring memory cheaply.** Use `add_visual_style_board`, `add_character_concept`, and `add_location_concept` for text-first mood, cast, location, and hero-prop development. Quote a small casting/look proof only when useful. Promote approved style artifacts so later episodes reuse IDs rather than copied prompt prose.
   - **Each principal becomes one Cast member with a true Consistent Character sheet**, in this order: (a) `add_character_concept` with name, role, backstory, wardrobe, personality, look notes; (b) `create_character_on_board` on the same board with that name and a description assembled from the card, **4:3** (one image approval; creates the Cast member and returns `castMemberId`); (c) `make_board_character_consistent` with the returned `boardItemId` (one image approval; the 7-panel identity sheet at 4:3, marked `isConsistentCharacter`, attached to the same Cast member); (d) `promote_character_concept` **only with `castMemberId` set** (link mode: fills the bible from the card, marks the card approved). Inspect the sheet: exactly 4 full-body rotations over 3 close-ups, nothing cropped; regenerate if not. A single portrait from an image model is not a Consistent Character.
   - **Never call `promote_character_concept` without `castMemberId` once a board character exists for that concept**: without it the tool creates a second Cast member, and the cleanup needs an `archive_character` approval that costs the user turns. Check `list_characters` before creating anything. If the tool version in use has no `castMemberId` parameter, skip promotion and update the concept card text instead.
   - **Locations get a master and a coverage set, not one plate.** For each recurring location: scout 2–3 candidates, lock one master (`add_location_concept` with the 6-axis description), then generate the plates the season's staging will need (establishing wide, reverse, and the two or three positions dialogue plays against) with the master in `referenceImageUrls` and the verbatim lighting key. Every recurring vehicle and hero prop gets its own plate. Record each plate with an id in `series-manifest.locations[].plates[]`; shots pin to those ids. This is the `elegiac-location-scout` lock-then-match pattern.
   - **Design the brand punctuation package once** (`branding.md`): series mark (file, typographic lockup, or a quoted generation), sonic sting (file, quoted `elevenlabs-sfx-v2` generation, or waiver), typography/colour from the StyleSystem using only fonts HyperFrames can supply, bookend ground treatment, Episode 1 versus later opening policy, end-card behaviour with a `nextText` pattern, and credits (`none` unless contractually required). Store it as `series-manifest.branding`, mirror a compact card on `00 — Series Bible`, and freeze any files into `brand/`. Brief the score with the sting's motif. No intro sequence, theme song, or credits are ever planned.
9. **Create one Episode Board, after the title is locked.** Name it `S01E01 — <Title>`; there is no rename tool, so a placeholder title becomes a manual chore for the user. Use `create_scene_development_board` or `create_scene_board_from_production_memory` when its required anchors resolve safely. Add/update the blueprint, script, `add_shot_list` artifact, anchors, and storyboard plan. During the alpha, structured local files plus roadmap/direction cards hold details not represented by a dedicated MCP artifact.
10. **Prove the episode.** Quote/cap 3–6 key vertical frames; default to four, and make two of them an **adjacent pair from one plate** (the geography test). Review hook image, cliffhanger image, identity, wardrobe, geography, vehicle identity, lighting, text zones, and safe zones with the `continuity-gate.md` checklist. Repair stills before motion.
11. **Produce only Episode 1.** Follow `production-pipeline.md`: coverage set, duration budget, dialogue stems, framed 9:16 stills for every cut in plate batches, the continuity gate and the stills animatic, MiniMax H3 Max Turbo clips at 768p (pilot batch first), VEED lipsync only where one visible mouth speaks; music/ambience afterwards if wanted. Use one action/camera instruction per clip. Preserve exact quote, deduction/refund, and idempotency facts.
12. **Finish through the edit contract.** Export/freeze the selected assets, copy the series branding package into the edit manifest with Episode 1's opening policy, validate and hash the manifest, build `BRIEF.md`, and route the fresh narrative edit to HyperFrames `general-video`. Captions are a sidecar, not burned in, unless the user asks. The user approves the final Studio preview before render.
13. **Close the loop.** Probe and package the render. Register it on the Episode Board only when the current upload path safely supports it. Update episode/loop status and return Production/Board links, local master, review proxy, captions, poster, manifests, credits, omissions, and the proposed Episode 2 handoff.

## Alpha storage contract

Treat current Board cards as rendered views of the canonical local `series-manifest.json`, `episode-blueprint.json`, and `edit-manifest.json`. Label their revision in the card title/body. Update an existing card when possible. A future structured artifact must be able to ingest these files without reinterpreting prose.

## Fast Track presentation

Do not force review of 60 rows. Show the show promise, movement map, principal cast/look, Episodes 1–10, and Episode 1 package; write all 60 promises to the production files. Cost, the continuity gate, the animatic, and render approvals still pause.
